# 重复读取稳定：下一步使用正常prebuilt基线

用户第二次现有boot探测返回同一id_tail12、status00、CRC b1bd5c8f、差异22488和相同首32字节。两次结果稳定，进一步支持docs/84的部分原厂前缀+FF后缀模型，不支持把这两次差异简单归为随机传输噪声。没有完整二进制读出，仍不宣称唯一重建内容。

0x6ac9=27337，即第106个零起始256字节页内偏移201，对应一基计数107页。旧recovery早期日志107页结束约2.111秒，而触摸复位在2.170秒、日志已报113页结束之后，边界并不精确重合。因此不能断言某一次旧recovery复位就是本次内容状态的来源，也不能确定产生时间。

下一步优先利用用户已经确认正常LineageOS+prebuilt kernel触摸正常的基线：正常启动一次，等原厂自动固件处理结束，保存dmesg中的版本和升级结果；随后回到当前诊断source boot，不重新编译，再probe同一内容。旧recovery中的行为不能替代正常LineageOS基线。

若正常prebuilt触摸恢复且source读取恢复到原厂CRC1655298b、差异0，进一步判断基础驱动是否已能工作；若内容变化但source仍不报告，继续核对启动/模式初始化；若prebuilt也失效或更新不成功，保留其日志，不自动重复擦写。当前没有新增C7/flash编程实现，没有改内核或要求新诊断版。
