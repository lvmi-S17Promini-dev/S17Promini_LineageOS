# 缺失FF固件页的受控修复与完整读写证据

本轮实际修改内核。已有CRC模型指向后段FF，但模型不是完整读出；因此加入完整快照和写前逐字节判断，不把推测的偏移当成可直接写入的依据。

## 数据修复规则

firmware_repair节点只接受root显式写repair-stock-0007，不在开机时执行。原厂文件仍须50192字节、CRC1655298b、版本0007；进入前完整读取，确认id_tail12和首32字节与原厂一致，保存写前50192字节备份。每个不同字节必须当前为FF，否则EUCLEAN拒绝，发生在状态初始化/页编程之前。

只对存在差异的256字节页编程，完整页数据取自经校验原厂文件。已有相同数据不变，缺失FF变成真实固件字节；不是给原厂文件补FF，更不是忽略CRC错误。采用原厂SPI初始化（包括01/02状态寄存器设置）、WREN06和PAGE_PROGRAM02包格式、每页就绪等待、完整读回比对、CRC和复位后版本查询。没有C7或其他擦除命令，不能修复需要0变1的非FF损坏；那种情况明确拒绝，不自动升级到擦除。

既有正确前缀在某个缺页内也会被同值再次编程，符合本次数据约束下1变0的方向；已相同的完整页跳过。即便所有内容已相同，仍可做初始化/完整校验/退出启动，written_pages为0。

## 读写与失败处理

改用268字节packet容量，覆盖12字节Flash头+256字节载荷；PRAM头仍11字节。Flash包header长度字段为payload+4，opcode02后BE24地址，所有边界/页对齐检查保留。每次写入要求完整I2C字节数，状态读取要求两个消息完整完成；每次就绪等待最多约2秒，全修复协议30秒deadline按事务检查，不能抢占一个已开始的控制器等待。

全过程暂停IRQ/轮询、持state/report锁；GPIO所有者的bias_lock覆盖编程、校验、低10ms/高后120ms退出及版本查询，避免显示复位插入。无自动重试。所有差异为0、CRC1655298b且版本0007才返回成功。失败不抹掉错误或伪造成功，备份保留；若编程中断，未完成内容不能保证可运行，需保留快照并评估后续恢复；旧prebuilt recovery可能再次截断固件，不能作为可靠恢复路径。

## 新诊断

* flash_dump：最近完整成功读取的50192字节，只读root二进制缓存；不是直接对芯片不断发读请求。
* flash_backup：修复入口保存的写前50192字节，只读root；不是整颗存储芯片的全容量备份。
* flash_status：首差异字节、实际FF总数/尾部连续FF长度、缓存/备份有效标志及原CRC/差异计数。
* flash_regions：每4KB的CRC、FF数、差异数，可定位代码区、参数区是否完整。
* firmware_status：初始化/写入/校验/版本阶段及written_pages，读回pages与实际编程页数分开。

缓存各约50KB，probe分配失败不阻止基础输入注册，但固件测试会在设备操作前返回ENOMEM。读到部分数据时缓存无效；首次完整读回结束才发布valid。非FF拒绝也保存当前备份。两个不同探测之间的数据可以变化，所以脚本的before.bin和内核实际修复前backup.bin都保存，不假定二者永远一致。

## 验证

主机模拟使用实际原厂文件和docs/84的截断模型，并提取当前读/初始化/等待/修复/版本及共享GPIO会话C函数。模拟90个缺失页成功补齐，完整50192字节与原厂相同、CRC1655298b、版本0007；测试非FF差异拒绝、编程失败、busy超时、错误版本与锁/复位清理。ASan/UBSan及-Wall -Wextra -Werror通过；mock总线拒绝C7等未允许opcode。测试不能代替芯片实测或证明SPI存储具体型号。源码checkpatch、空白及脚本语法检查通过，未运行内核编译/手机编程。

## 手动测试

刷入新boot后更新tools/test_s17_touch_pram.sh，保留已推送的原厂bin。亮屏root shell执行：

```
sh /data/local/tmp/test_s17_touch_pram.sh /data/local/tmp/s17-ff-repair /data/local/tmp --repair
```

这是显式写触摸存储的测试。脚本先只读prepare并把before.bin落到/data，再请求受控修复，保存内核实际backup.bin、读回readout.bin、分段信息、进度与dmesg。默认脚本不启用repair。成功后给八秒触摸窗口；若失败保留全部输出，不自动重复。无需设置环境变量或改vendor。
